## Supported host

This core release supports exactly OpenCode `0.0.0-beta-19086`. OpenCode 1 and
OpenCode 2 use different plugin ABIs.

## Install

```sh
weave init --harness opencode2 --scope local --yes
```

The installer edits the plural `plugins` field in project JSONC. Use
`--scope global` for the XDG OpenCode config. A manual entry is:

```jsonc
{
  "plugins": [
    "@weaveio/weave-adapter-opencode@<exact-version>",
  ],
}
```

The package root resolves its native server entry. Do not append `/plugin`.
Restart OpenCode after changing package versions.

## Native behavior

The adapter registers materialized Weave agents, live model and variant
references, request temperature, configured skills, and current native
permission rules. It preserves foreign same-ID agents. It delegates through
OpenCode's native `subagent` action for both foreground and background work.

Use one plan command:

```text
/weave:start <plan-name>
```

The V2 plugin does not register `/start-work`. Plan selection and the CLI task
list are read-only display metadata. They do not create or resume a durable
workflow.

## Tool mapping

| Weave capability | OpenCode actions |
| --- | --- |
| `read` | `read`, `glob`, `grep` |
| `write` | `edit` |
| `execute` | `shell` |
| `delegate` | `subagent` for eligible targets |
| `network` | `webfetch`, `websearch` |

`allow`, `deny`, and `ask` remain distinct. Arbitrary MCP or custom tool
mappings are not part of this release.

## Known limits

OpenCode `0.0.0-beta-19086` does not expose its native skill permission
assertion at prompt admission. Configured available skills attach without that
check. Disable the skill in `.weave` when this limit is not acceptable.

Durable workflows, usage rollups, a child dashboard, automatic model fallback,
provider acceleration, and `/weave:goal` are not delivered. The current DSL
does not define `fast`.

See the repository's OpenCode adapter guide for refresh, RPC, TUI, and isolated
verification details.
