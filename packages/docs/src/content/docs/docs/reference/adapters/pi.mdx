## Install

The Pi adapter is implemented, but its package is distributed through the nightly channel only. Pi loads the extension through its package installer:

```text
pi install npm:@weaveio/weave-adapter-pi@nightly
```

The adapter requires Pi `>=0.81.1` and runs in the Bun-based Pi environment.

## Activate Weave

Start Pi in a project with a valid `.weave/config.weave`. The extension checks trust, configuration, and capabilities before activation. If those checks cannot pass, it enters **health-only** mode: health and diagnostic commands remain available, but configuration-driven execution is disabled.

Fix the reported configuration or installation issue, then restart Pi to activate the full adapter.

## Switch agents

Use `Alt+A` to cycle through healthy primary agents. The active agent is shown in Pi's interface. Switching changes the active Weave agent without changing the project configuration.

## Commands

The extension exposes these commands:

- `/weave:start` — start configured work.
- `/weave:run` — run a durable workflow.
- `/weave:resume` — resume recorded work.
- `/weave:advance` — advance the active workflow.
- `/weave:abort` — stop active work.
- `/weave:status` — inspect workflow status.
- `/weave:health` — inspect activation health.
- `/weave:plan` — inspect the current plan.
- `/weave:artifact` — inspect an available artifact.
- `/weave:goal <plan-name>` — run a plan in the foreground goal loop.

### Goals and workflows

Use `/weave:goal <plan-name>` to pursue a plan in Pi's foreground loop. `/weave:goal status` shows status; `/weave:goal pause`, `/weave:goal resume`, and `/weave:goal clear` control it. `check` aliases status, `stop`, `off`, `reset`, `none`, and `cancel` alias clear. Use `-- <plan-name>` to select a plan whose name collides with a control word; `/weave:goal` accepts a plan name, not inline goal prose.

In health-only mode, the goal `start` and `resume` forms are blocked; `status`, `pause`, and `clear` remain available, including their aliases. Delegated child mode is inert for goal restore, prompt, tool, continuation, and footer behavior.

Goal completion comes from the plan's completion decision, reported through Pi's private goal tool. The footer shows the plan, task, and a 72-code-point progress ladder. Plan refreshes follow lifecycle and command events; the timer refreshes metrics only.

This is separate from `/weave:run`, which starts a durable workflow with persisted workflow state.

## Private children

Pi can run private child agents for delegated work and direct workflow steps. Child sessions inherit the authenticated configuration and count toward the configured parallel-child limit. Finished children release that capacity.

The optional child inspector is adapter-owned and local-only. Its exact `child_inspection` defaults, bounds, private storage path and permissions, controls, commands, quotas, trim markers, clear behavior, recovery scope, resume limits, export boundary, and privacy rules are defined by the repository's [amended Spec 33](https://github.com/weaveio/weave/blob/main/docs/specs/33-spec-pi-adapter/33-spec-pi-adapter.md). [ADR 0013](https://github.com/weaveio/weave/blob/main/docs/adr/0013-pi-private-child-sessions.md) records why this history does not belong to the engine. Private history may contain sensitive raw content; it is not an engine transcript, workflow recovery store, telemetry stream, or exported transcript.

See [Prompts, models, and policy](../../../prompts-models-policy/) for delegation intent and the [support matrix](./) for distribution status.
