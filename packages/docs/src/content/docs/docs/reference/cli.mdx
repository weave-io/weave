The CLI creates, validates, composes, and inspects configuration. It does not launch a harness runtime. Run `weave --help` for the installed version's command list. Adapter-specific limitations are listed in the [support matrix](../adapters/).

## Common flags

| Flag | Meaning |
| --- | --- |
| `--help`, `-h` | Show help. |
| `--version`, `-V` | Show the CLI version. |
| `--json` | Emit JSON for commands that support it, including `validate` and prompt list/inspect. |
| `--yes`, `-y` | Accept init or migration prompts. |
| `--force` | Allow supported overwrites. |
| `--scope global\|local` | Select a scope for `init`, migration, or prompt self-modification. |

## `weave init`

Create configuration and configure detected harnesses:

```sh
weave init
weave init --scope local --yes
weave init --scope global --yes
weave init --scope local --install-dir .weave --yes
weave init --scope local --harness opencode --yes
weave init --scope local --all-harnesses --yes
```

`--install-dir` changes the scaffold location. `--harness` selects one detected harness; `--all-harnesses` selects every detected harness. The current installer supports OpenCode. Claude Code uses [`weave compose`](#weave-compose), and Pi uses its extension installer.

## `weave init migrate`

Convert a supported legacy OpenCode JSONC configuration into `.weave`:

```sh
weave init migrate --scope local
weave init migrate --scope global
weave init migrate --scope local --yes
weave init migrate --scope local --yes --force
```

Review the generated configuration and validate it before use.

## `weave validate`

Validate one scope or an explicit file:

```sh
weave validate
weave validate --project
weave validate --global
weave validate --path .weave/config.weave --json
```

Without a selector, the CLI loads the effective configuration. Exit `0` means valid; exit `1` means a read, parse, validation, or merge failure.

## Prompt commands

```sh
weave prompt list
weave prompt list --json
weave prompt inspect loom
weave prompt inspect loom --json
weave prompt self-modify --scope local
```

`prompt inspect <agent>` renders a composed prompt and metadata. `prompt self-modify` prints a text-only guide and accepts only `--scope`; it does not edit files or support `--json`.

## `weave runtime`

Inspect runtime state for the current project root without starting or changing a harness. Runtime commands have no scope selector or JSON output:

```sh
weave runtime status
weave runtime journal --limit 20
```

## `weave eval run`

Run text-based evaluation cases:

```sh
weave eval run --case loom-route-backend-api
weave eval run --case loom-route-backend-api --agent loom --model anthropic/claude-sonnet-4.5
weave eval run --case loom-route-backend-api --dry-run
weave eval run --case loom-route-backend-api --raw-artifacts
```

Use `--agent`, `--model`, and `--case` to filter. `--dry-run` validates filters without making model calls. Results cover text-observable behavior, not hidden tool activity or live harness events.

## `weave compose`

Compose adapter output. The CLI currently supports Claude Code:

```sh
weave compose --adapter claude-code
weave compose --adapter claude-code --init
weave compose --adapter claude-code --project-root ./project
weave compose --adapter claude-code --out-dir .weave/plugins/claude-code
```

`--init` also creates the separate bootstrap plugin at `./weave-bootstrap-plugin` by default. Use `--bootstrap-dir` to choose its location; `--out-dir` controls the composed Claude Code output only.

## `weave run`

`weave run` does not start a harness. Launch the harness yourself and use its adapter-native start command, such as OpenCode's `/weave:start` or Pi's `/weave:start`.

There is no current `weave build` command.
