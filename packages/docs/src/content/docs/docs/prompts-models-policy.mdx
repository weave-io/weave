## Compose a prompt

Use an inline prompt for short text or a file for longer instructions:

```weave
agent reviewer {
  prompt_file "reviewer.md"
  prompt_append "Return findings with file and line references."
}
```

Prompt appends are added after the primary prompt. Use `prompt_append_file` instead of `prompt_append` when the appended instructions need their own file; the two fields are mutually exclusive. Prompt templates can use the context supplied by the adapter, such as `{{instance.goal}}` in a workflow step.

Inspect the rendered result with:

```sh
weave prompt inspect reviewer
```

## Prefer models

Declare an ordered list. The harness resolves the first usable option:

```weave
agent planner {
  models ["claude-sonnet-4-5", "gpt-5"]
}
```

This is a preference, not a guarantee. Availability, authentication, and harness-specific model names remain outside Weave.

### Pi runtime fallback

On Pi, the adapter may try the next usable model after Pi finishes its own
retry, overflow-compaction, and queued-message recovery. This optional behavior
uses the same process and native session, but it is a second low-level run. The
visible child or tool stays pending while Weave starts that run with a hidden
custom message. Pi `0.84.2` is the exact-tested host; the `0.81.1` floor keeps
legacy settlement when the public fallback surfaces are missing or unproven.

A manual model change disables automatic fallback until you explicitly activate
a Weave agent again. Candidates stay in declared order, and a context-overflow
failure may use only a model with a larger declared context window. A successful
model application remains the reported model even if recovery later fails. Only
a recovery-confirmed switch produces the read-only Model Fallback event; an
applied-only switch or exhausted list produces no event. See the [Pi adapter
reference](../reference/adapters/pi/) for lifecycle and provider-context rules.

## Set abstract tool policy

```weave
agent reviewer {
  tool_policy {
    read allow
    write deny
    execute ask
    network deny
    delegate allow
  }
}
```

The capabilities are `read`, `write`, `execute`, `network`, and `delegate`. Permissions are `allow`, `deny`, and `ask`. Adapters map this policy to native controls; unsupported controls cannot be made identical across harnesses.

## Self-modify through the CLI

The public command contract is:

```sh
weave prompt self-modify --scope local
```

The command prints the self-modification guide for the selected scope; it does not write the change itself. Validate the configuration after applying any instructed edit.
