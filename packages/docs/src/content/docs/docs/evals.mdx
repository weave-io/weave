## What `weave eval run` Is

`weave eval run` is Weave's eval entry point for local verification and CI. It runs the registered eval suites against the built-in model matrix and writes a run summary plus report artifacts.

This surface is intentionally narrow today. It is for **text-only prompt evals**, not harness-runtime execution.

## Supported Suite Families

The current public surface supports eight suite families:

- `loom-routing`
- `tapestry-execution`
- `tapestry-category-routing`
- `shuttle-execution`
- `spindle-tools`
- `pattern-planning`
- `weft-review`
- `warp-security`

These are the canonical suite IDs used by filters, fixtures, and reports. The `--agent` flag also accepts the short aliases `loom`, `tapestry`, `shuttle`, `spindle`, `pattern`, `weft`, and `warp`. `tapestry` matches both `tapestry-execution` and `tapestry-category-routing`.

Loom's eligible delegation targets are not a hardcoded list in the eval fixtures. They are derived by composing the `loom` agent through the engine's `composeAgentDescriptor()` API and reading its resolved `delegationTargets`, so a config change that adds or removes a target is reflected automatically. See `docs/agent-evals.md` for the composition-derived coverage preflight.

## Text-only Boundary

Current evals score only what is visible in assistant text. They are useful for checking routing, structure, delegation signals, review format, planning shape, and similar text-observable behavior.

What they do **not** do:

- run a real harness session
- verify actual tool calls or hidden tool telemetry
- inspect filesystem mutations, shell history, browser events, or network traces

Runtime-backed trajectory evals are no longer an explicit non-goal of the overall eval contract; see "Harness Trajectory Evals" below for the parallel track that does observe real harness sessions. Text-only cases specifically still must not assert on runtime behavior, and that boundary stays enforced by the fail-closed suite registry described here.

## Harness Trajectory Evals

Alongside the text-only track, Weave ships a second, parallel eval track that observes a real harness session end to end: **harness trajectory evals**. This is documented in [ADR 0008](https://github.com/weave-io/weave-vnext/blob/main/docs/adr/0008-harness-trajectory-evals.md) (Accepted, 2026-09-03) and formalized in Spec 33.

Trajectory cases run a real harness session (currently OpenCode) in a Podman sandbox with a per-case ephemeral workspace, a wall-clock timeout, auto-approved permissions, and no network egress beyond the model provider. The adapter emits a normalized event stream that the runner scores against expectations such as which subagents were spawned and which tools were called.

Only a small, bounded set of fields from that observation is published, never raw session transcripts or tool arguments:

- `harnessDelegatedCorrectly`
- `observedSpawns`
- `observedToolCalls`
- `harnessCompletedWithoutError`

As of this writing, this track is at Phase 1: one case, one model (`openai/gpt-4o-mini`), one sandbox configuration. It proves the mechanism works end to end on a real harness; it is not yet as broad as the eight text-only suites, and it should be read that way. Text-only evals remain the primary, broadest-coverage surface for prompt and structural quality.

## Deferred Scope

Some behavior is deliberately out of reach for a text-only eval surface, not silently missing:

- **Tapestry fan-out** (concurrently delegating to multiple category shuttles) is not exercised end to end; `tapestry-category-routing` only proves the text names the correct single category shuttle.
- **Runtime tool-call telemetry** is never inspected, only what assistant text claims.
- Any suite that stays below an 80% pass rate across published runs should be treated as deferred and diagnosed with evidence, not silently patched. See `docs/agent-evals.md` for the current status of suites in that state.

## Basic Usage

Run all suites against the default model set:

```bash
weave eval run
```

Filter to one suite family:

```bash
weave eval run --agent loom
weave eval run --agent shuttle
```

Filter to one model or one case:

```bash
weave eval run --model anthropic/claude-sonnet-4.5
weave eval run --case loom-route-backend-api
```

Preview what would run without making model calls:

```bash
weave eval run --dry-run
weave eval run --agent loom --model anthropic/claude-sonnet-4.5 --dry-run
```

Filters use exact-match semantics. Dry-run keeps the same filter validation, but skips live model execution.

## Artifacts and Reporting

Each run produces a small set of high-level artifacts under `eval-bundles/`, including:

- a run summary with pass/fail rollups
- per-suite score outputs
- prompt-hash provenance records
- a public JSON report
- a human-readable Markdown report

Published reporting is sanitized and structured for dashboards and historical comparisons. Raw prompt or transcript artifacts are a separate local-only debugging path and are not part of the public reporting surface.
