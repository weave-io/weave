Weave is a harness-agnostic configuration layer. A `.weave` file describes the agents, categories, prompts, model preferences, tool policy, and workflows you want. An adapter maps that intent to a supported harness.

## The model

- **Agents** are named roles with prompts, model preferences, and capabilities.
- **Categories** describe domains. Weave can turn a category into a `shuttle-<name>` agent.
- **Workflows** define ordered steps and their completion signals.
- **Settings** control shared behavior, such as permission enforcement.
- **Adapters** translate the normalized configuration for OpenCode, Claude Code, or Pi.

Weave describes intent. The harness still owns its native user interface, model availability, and execution behavior.

## Configuration scopes

A project configuration lives at `.weave/config.weave`. A global configuration lives at `~/.weave/config.weave`. When both exist, global values load first and project values apply on top: scalars override, objects deep-merge, and arrays union-merge. Prompt files are resolved from the matching `.weave/prompts/` directory.

Use `weave validate --project` or `weave validate --global` to check one scope. Other inspection commands use the effective configuration from the current project root.

## Intent is not a model guarantee

A `models` list is an ordered preference. The adapter and harness decide whether a model is available and how to select it. Weave does not provision model access.

Likewise, `tool_policy` expresses abstract permissions. Each adapter maps those permissions to the controls its harness supports.

## Execution boundaries

Weave can materialize configuration and expose workflow operations, but it does not replace a harness. Use the adapter page for the commands and runtime behavior of your chosen harness.
