## Where configuration lives

Weave reads two optional files:

| Scope | File | Use |
| --- | --- | --- |
| Global | `~/.weave/config.weave` | Defaults shared across projects. |
| Project | `.weave/config.weave` | Settings for the current project. |

Prompt files belong in the `prompts/` directory beside the selected config file.

Create either scope with:

```sh
weave init --scope local --yes
weave init --scope global --yes
```

## Merge order

Weave loads bundled defaults first, then global values, then project values:

```text
builtins < global < project
```

- Scalars override earlier values.
- Objects deep-merge recursively.
- Arrays union-merge, keeping the later declaration's entries first and removing duplicates.

Keep shared defaults global and project-specific agents, prompts, and workflows local. Use `weave validate --project` and `weave validate --global` to validate each scope independently.

## Prompt paths

A `prompt_file` or `prompt_append_file` value names a file under the scope's `prompts/` directory:

```weave
agent reviewer {
  prompt_file "reviewer.md"
  prompt_append_file "reviewer-rules.md"
}
```

Use [Prompts, models, and policy](../prompts-models-policy/) for composition rules.

## Migrate a legacy configuration

If you have a supported legacy OpenCode configuration, ask the CLI to convert it:

```sh
weave init migrate --scope local
```

Add `--yes` to accept the migration without prompts. Review the generated `.weave/config.weave`, then validate it before using an adapter.

## Inspect the result

```sh
weave prompt list
weave prompt inspect reviewer
weave runtime status
```

Run prompt and runtime inspection from the project root. The [CLI reference](../reference/cli/) lists command-specific flags.
