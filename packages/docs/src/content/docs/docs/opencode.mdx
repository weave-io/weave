## Support status

The current native adapter supports exactly OpenCode `0.0.0-beta-19086`. It
uses OpenCode 2 server, RPC, and Solid CLI plugin APIs. It does not load as an
OpenCode 1 plugin.

## Install

```bash
weave init --harness opencode2 --scope local --yes
```

Manual configuration uses the plural `plugins` field and the bare package
name:

```jsonc
{
  "plugins": [
    "@weaveio/weave-adapter-opencode@<exact-version>",
  ],
}
```

Do not append `/plugin`. Use `--scope global` to edit the XDG OpenCode config.
The installer preserves comments, options, and unrelated keys, and refuses
ambiguous or malformed config files.

## What the plugin registers

The Location-scoped server materializes Weave agents through native transforms.
It resolves `provider/model#variant` entries against OpenCode's live catalog,
applies temperature through the request context, maps abstract tool policy to
current native actions, and attaches configured available skills.

It registers one plan command:

```text
/weave:start <plan-name>
```

The V2 plugin does not register `/start-work`. It validates one existing plan,
selects the owned Tapestry agent and resolved model, and submits one visible
foreground prompt. The selected-plan record powers read-only display only. It
does not create, resume, or advance a durable workflow.

## Tool policy and delegation

The adapter maps read to `read`/`glob`/`grep`, write to `edit`, execute to
`shell`, network to `webfetch`/`websearch`, and eligible delegation to native
`subagent` rules. It preserves `allow`, `deny`, and `ask`.

OpenCode owns foreground and background child execution, result delivery,
navigation, steering, and interruption. Weave does not run a second scheduler
or use private child-session inputs.

## Read-only plan UI

The separate CLI plugin shows plan progress beside the composer and provides a
**Weave: Plan tasks** palette action. It reads bounded server RPC output, not
project files. Headless clients can call the same RPC but do not load the CLI
component.

## Refresh and ownership

The adapter shares one in-flight refresh and publishes only a complete valid
catalog. Broken edits keep the last valid catalog. Native registry replay adds
only absent agent IDs and does not apply Weave hooks to foreign colliding
agents.

The reserved `weave:start` command name can replace another same-name command
because this host has no atomic command presence check.

## Known limits

OpenCode `0.0.0-beta-19086` does not expose its native skill permission
assertion at prompt admission. Configured available skill IDs attach without
that check. Disable a skill in `.weave` when this is not acceptable.

This release does not include durable workflows, usage rollups, a child
dashboard, automatic model fallback, provider acceleration, or `/weave:goal`.
The current DSL does not define `fast`.

## Verify

Run repository unit, type, lint, build, and link checks. The repository's
OpenCode 2 verification guide adds an isolated packaged-runtime proof and a
separate interactive TUI proof against the exact host.
