---
title: Workflows
description: Define ordered, explicit work in the Weave DSL.
---

A workflow is a named sequence of steps. Each step selects an agent, provides a prompt, and declares how completion is recognized.

```weave
workflow quick-fix {
  description "Fix and review a small change"
  version 1

  step fix {
    name "Implement the fix"
    type autonomous
    agent shuttle
    prompt "Fix: {{instance.goal}}"
    completion agent_signal
  }

  step review {
    name "Review the result"
    type gate
    agent reviewer
    prompt "Review the completed fix."
    completion review_verdict
  }
}
```

## Step types

- `autonomous` lets the selected agent perform the step.
- `interactive` expects user participation.
- `gate` waits for a review or approval signal.

Completion methods include `agent_signal`, `user_confirm`, `plan_created`, `plan_complete`, and `review_verdict`. Steps can declare `inputs`, `outputs`, `role`, and `on_reject` where the schema supports them.

## Extend planning

A project can insert a reusable step before planning:

```weave
step collect-context {
  name "Collect context"
  type autonomous
  agent shuttle
  prompt "Collect context before planning."
  completion agent_signal
}

extend before-plan ["collect-context"]
```

The [DSL reference](../reference/dsl/) documents extension syntax and current values.

## Start work

Workflow execution is adapter-specific. OpenCode exposes `/weave:start` and `/start-work`; Pi exposes `/weave:start`. Claude Code receives materialized configuration but does not provide OpenCode-style runtime commands. See the [adapter support matrix](../reference/adapters/).
