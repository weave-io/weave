## Install

The Pi adapter is implemented, but its package is distributed through the nightly channel only. Pi loads the extension through its package installer:

```text
pi install npm:@weaveio/weave-adapter-pi@nightly
```

The adapter requires Pi `>=0.81.1` and runs in the Bun-based Pi environment.

## Activate Weave

Start Pi in a project with a valid `.weave/config.weave`. The extension checks trust, configuration, and capabilities before activation. If those checks cannot pass, it enters **health-only** mode: health and diagnostic commands remain available, but configuration-driven execution is disabled.

Fix the reported configuration or installation issue, then restart Pi to activate the full adapter.

## Switch agents

Use `Alt+A` to cycle through healthy primary agents. The active agent is shown in Pi's interface as `◆ WEAVE · <AGENT>`. Each agent name always carries the same background tint, chosen deterministically from the background tokens the active theme supports, so one color means one agent in every session. Different agents may share a color. If the theme provides no background support, the badge renders the agent name in accent bold with no tint. Switching changes the active Weave agent without changing the project configuration.

## Commands

The extension exposes these commands:

- `/weave:start` — start configured work.
- `/weave:run` — run a durable workflow.
- `/weave:resume` — resume recorded work.
- `/weave:advance` — advance the active workflow.
- `/weave:abort` — stop active work.
- `/weave:status` — inspect workflow status.
- `/weave:health` — inspect activation health.
- `/weave:plan` — inspect the current plan.
- `/weave:artifact` — inspect an available artifact.

### Start work and run workflows

`/weave:start` is the only plan-execution command. It confirms an existing plan and submits it as one visible foreground Pi turn. It records no durable workflow state.

`/weave:run` does one separate thing: it explicitly starts a named durable workflow that the engine manages and persists. Neither command implies the other, and `/weave:start` never starts a durable workflow on your behalf.

### Track the active task

While a durable workflow is active, Pi shows one bounded `weave-task` status entry naming the current task, such as `▸ task 3/10 · 3. Update the adapter docs`. Long titles are shortened with a single ellipsis.

The entry clears when there is nothing active: no tracked workflow, no readable plan task, a completed, failed, or cancelled workflow, or a lookup Weave could not read. If your session tracks no workflow but Weave finds an eligible recovered pointer, the entry may show that paused plan as read-only state. Continue it with `/weave:resume`; showing it starts nothing.

Press `Alt+T` to open the read-only plan-task list. It reads the same active plan and recovery state as the status entry, marks each task `[ ]`, `[~]`, or `[x]`, and opens on the active task. Your configured Pi keybindings drive it: `tui.select.up` and `tui.select.down` scroll, `tui.select.cancel` closes, and the hint line names the keys you actually have bound. The list scrolls and closes; it starts, resumes, advances, and cancels nothing.

When no plan is available or Weave cannot read the plan or workflow, the list reports a short notice instead of opening a stale or empty view.

## Provider acceleration is unsupported

An agent's `fast true` is neutral intent in Pi. The adapter carries that intent on the active agent and on authenticated child sessions, and never turns it into a provider control.

Pi's extension contract exposes provider header, request, and response hooks, but none of them proves the effective transport of one prepared request together with that same request's official response body. Without that evidence, an acceleration claim would be a guess.

The adapter therefore registers no provider header, request, or response handler. It mutates no provider request payload and no header, and it never writes `service_tier`, `speed`, or `anthropic-beta`. The `provider-fast-activation` capability reports `unsupported` with the bounded reason `harness-seam-unavailable`.

This is an optional-capability gap. It warns, never enters health-only mode, and never blocks activation, prompts, models, tools, delegation, or child bootstrap. `/weave:status` may show `fast: unsupported (harness-seam-unavailable)`; it never reports acceleration as applied, active, or confirmed.

Support can be enabled only after Pi exposes a documented seam that reports the effective transport of one prepared request plus correlated official response-body evidence for that same request, proven in a fresh real harness. Unit coverage is not that proof.

## Private children

Pi can run private child agents for delegated work and direct workflow steps. Child sessions inherit the authenticated configuration and count toward the configured parallel-child limit. Finished children release that capacity.

The optional child inspector is adapter-owned and local-only. Its exact `child_inspection` defaults, bounds, private storage path and permissions, controls, commands, quotas, trim markers, clear behavior, recovery scope, resume limits, export boundary, and privacy rules are defined by the repository's [amended Spec 33](https://github.com/weaveio/weave/blob/main/docs/specs/33-spec-pi-adapter/33-spec-pi-adapter.md). [ADR 0013](https://github.com/weaveio/weave/blob/main/docs/adr/0013-pi-private-child-sessions.md) records why this history does not belong to the engine. Private history may contain sensitive raw content; it is not an engine transcript, workflow recovery store, telemetry stream, or exported transcript.

See [Prompts, models, and policy](../../../prompts-models-policy/) for delegation intent and the [support matrix](./) for distribution status.
