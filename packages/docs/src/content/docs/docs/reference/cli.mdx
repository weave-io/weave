`weave` creates and validates configuration, composes Claude Code files, and
inspects local Weave state. It does not launch OpenCode, Claude Code, or Pi.
Run `weave --help` to print the installed command list and options.

See the [adapter support matrix](../adapters/) for harness-specific behavior.

## Usage

```text
weave <command> [options]
```

## Commands

The current `weave --help` output lists these commands:

| Command | Purpose |
| --- | --- |
| `weave init` | Create Weave configuration and install supported harness integrations. |
| `weave prompt inspect <agent>` | Render one composed agent prompt. |
| `weave prompt list` | List available agent names. |
| `weave prompt self-modify` | Print the self-modification guide. |
| `weave validate` | Validate `.weave` configuration files. |
| `weave runtime status` | Show Runtime Store status. |
| `weave runtime journal` | Show recent journal entries. |
| `weave adapter pi …` | Run bounded Pi child and doctor commands. |
| `weave eval run` | Run configured text-only evals. |

`weave compose` is also implemented for Claude Code. It is documented in
[Claude Code](../adapters/claude-code/).

## Options

| Option | Meaning |
| --- | --- |
| `--help`, `-h` | Show help. |
| `--version`, `-V` | Show the CLI version. |
| `--scope global\|local` | Select the scope for `init` or `prompt self-modify`. |
| `--install-dir <dir>` | Choose the `init` configuration directory. |
| `--path <file>` | Validate an explicit `.weave` file. |
| `--project` | Validate `./.weave/config.weave`. |
| `--global` | Validate `~/.weave/config.weave`. |
| `--json` | Emit machine-readable output where supported. |
| `--yes`, `-y` | Accept safe non-interactive defaults. |
| `--agent <name>` | Filter evals to one agent. |
| `--model <id>` | Filter evals to one model. |
| `--case <id>` | Filter evals to one case. |
| `--dry-run` | Preview an eval without a model call. |
| `--raw-artifacts` | Write raw eval artifacts locally for debugging. |

Command-specific options include `--harness`, `--all-harnesses`, `--force`,
`--namespace`, `--limit`, `--adapter`, `--project-root`, `--out-dir`,
`--init`, `--bootstrap-dir`, `--diagnostic`, `--content`,
`--content-cursor`, `--cursor`, and `--parent-session`.

## `weave init`

Create a local or global configuration:

```sh
weave init
weave init --scope local --yes
weave init --scope global --yes
weave init --scope local --install-dir .weave --yes
weave init --scope local --harness opencode --yes
weave init --scope local --all-harnesses --yes
```

The current installer writes OpenCode integration files. Claude Code uses
`weave compose --adapter claude-code`; Pi uses its package installer. Local
writes keep project-trust and collision checks in both interactive and
`--yes` modes.

## `weave init migrate`

Convert a supported legacy OpenCode JSONC file into canonical `.weave` DSL:

```sh
weave init migrate --scope local
weave init migrate --scope global
weave init migrate --scope local --yes --force
```

Migration keeps the legacy source, warns for unsupported fields, writes the
canonical scope destination, and validates the generated file. `--force`
allows an existing destination and creates a backup. `--install-dir` is ignored
in migrate mode.

## `weave validate`

Validate the effective configuration, one scope, or one file:

```sh
weave validate
weave validate --project
weave validate --global
weave validate --path .weave/config.weave --json
```

Exit `0` means valid. Exit `1` reports a read, parse, merge, or schema error.
Validation does not write configuration or materialize an adapter.

## Prompt commands

```sh
weave prompt inspect <agent>
weave prompt inspect <agent> --json
weave prompt list
weave prompt list --json
weave prompt self-modify --scope local
```

`inspect` renders the composed prompt and bounded metadata. `list` prints
normalized names. `self-modify` prints a read-only guide and does not edit
files.

## Runtime inspection

Run these commands from the project root:

```sh
weave runtime status
weave runtime journal --limit 20
weave runtime preferences
weave runtime preferences --namespace adapter-pi --limit 20
```

Runtime inspection reads `.weave/runtime/weave.db` without creating or
migrating it. It reports status, sanitized journal entries, or stored adapter
preferences. It does not start a workflow or expose prompts, transcripts,
credentials, tokens, or provider payloads.

## Pi adapter commands

```sh
weave adapter pi children list [--json] [--diagnostic]
weave adapter pi children show <id> [--json] [--content] [--cursor <c>] [--parent-session <id>]
weave adapter pi children result <id> [--json] [--cursor <c>] [--parent-session <id>]
weave adapter pi children delete <id> [--yes] [--json] [--parent-session <id>]
weave adapter pi doctor [--json] [--diagnostic]
```

The commands provide local, bounded adapter inspection and maintenance.
`children show --content` returns a sanitized projection. `children result`
returns byte-exact result pages. `children delete` intentionally appends a
tombstone and asks for confirmation unless `--yes` is present. `--diagnostic`
adds bounded diagnostic fields but never exposes an absolute native session
path. These commands do not start, resume, or execute workflow work.

## `weave eval run`

```sh
weave eval run
weave eval run --agent <name> --model <id> --case <id>
weave eval run --dry-run
weave eval run --raw-artifacts
```

Filters select agents, models, and cases. `--dry-run` validates selection and
makes no model call. Live execution needs the configured model-service key.
Raw artifacts are local-only debugging output.

## `weave compose`

Compose the Claude Code plugin from the effective configuration:

```sh
weave compose --adapter claude-code
weave compose --adapter claude-code --init
weave compose --adapter claude-code --project-root ./project
weave compose --adapter claude-code --out-dir .weave/plugins/claude-code
```

`--init` creates the optional bootstrap plugin. `--out-dir` selects generated
Claude Code files, and `--bootstrap-dir` selects the bootstrap directory.
Generated files provide agents and prompts; they do not provide a durable
workflow runtime.

## Errors and exit status

The CLI returns zero for successful commands and one for expected command
errors. `--help` and `--version` print their output without changing config or
runtime state.
